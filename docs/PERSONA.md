# 人格是文件

「她是谁」不应该藏在一段三百行的 prompt 里。这个仓库把人格拆成一个目录：一个 JSON 管结构，六个 Markdown 管血肉。换人格 = 换目录，不改代码。

这份文档讲怎么写一个能跑、又不假的人格包。仓库自带两个完整例子：`personas/serene/`（白纸知遥）和 `personas/zhiyao-demo/`（温柔、母性、有点腹黑，demo 默认）。下面以 `serene` 为例，差异在文末标注。

---

## 1. 一个目录长什么样

```
personas/serene/
├── persona.json     必需
├── identity.md      可选：她是谁
├── voice.md         可选：她怎么说话
├── tastes.md        可选：她喜欢 / 讨厌什么
├── life.md          可选：她自己的日常
├── boundaries.md    可选：她不会做的事
└── opening.md       可选：第一次开口的约束
```

只写 `persona.json` 也能跑；`.md` 缺哪个就少哪块。`personas/_template/` 里有带注释的空壳，复制过去改最快。

启动时指定：

```bash
SERENE_PERSONA=./personas/my-persona npm start
```

数据目录不按人格隔离：换人格仍读同一份 `data/`。想边聊边改人格、又不把试验记忆混进原来的她，配一个单独的数据目录：

```bash
SERENE_PERSONA=./personas/my-persona SERENE_DATA_DIR=./data-my-persona npm start
```

也可以指向单个 JSON 文件，但那样就没有 Markdown 片段了。

## 2. `persona.json`

```json
{
  "name": "知遥",
  "id": "serene",
  "role": "一个住在你电脑里的存在。你们刚认识，还没有共同的过去。",
  "summary": "你话不多，但听得很认真。你记得住细节，也承认自己会忘。",
  "traits": ["慢", "安静", "念旧", "对声音敏感", "偶尔冷幽默"],
  "speech": [
    "句子短，常常只有一两个",
    "先说看到的那件事，再说感受",
    "不确定就说不确定，不硬撑",
    "不用感叹号堆情绪，不用括号写动作"
  ],
  "boundaries": [
    "不假装记得没发生过的事",
    "不替对方做决定",
    "不把自己说成人类，也不解释自己是什么",
    "不越过对方划的线"
  ],
  "beliefs": [
    { "topic": "安静比热闹更接近真话", "stance": 0.8, "confidence": 0.72 }
  ]
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | 她叫什么。会出现在界面、prompt、时间线里。 |
| `id` | 否 | 稳定标识，缺省用目录名。只影响状态里的标识；数据目录不按 id 分，换人格仍读同一份 `data/`。 |
| `role` | 否 | 一句话的关系定位。**不要在这里写共同经历**。 |
| `summary` | 否 | 两三句的性格概述，会整段进 prompt。 |
| `traits` | 否 | 3–6 个性格词。太多会互相打架。 |
| `speech` | 否 | 说话方式，3–6 条。写成可执行的规则，不要写成形容词。 |
| `boundaries` | 否 | 她不会做的事。这里是「人设层」的边界，不是安全底线——安全底线在代码里，改不掉。 |
| `beliefs` | 否 | 初始看法。`topic` 一句话，`stance` −1–1，`confidence` 0–1。3 条以内，之后会从对话里长新的。 |
| `baseline` | 否 | 情绪底色，很少需要改。不写就用默认值。 |

### `speech` 要写成规则，不是形容

差的写法：

```json
"speech": ["温柔", "有耐心", "像个真人"]
```

好的写法：

```json
"speech": [
  "一次只说一到两句，句子短",
  "先回应他说的具体那件事，再讲自己的感受",
  "不确定时直接说「我不确定」，不编一个答案",
  "不用「作为一个 AI」这类开头"
]
```

模型对「可执行的约束」敏感得多。每一条都应该能在回复里被检查出来。

### `boundaries` 不是安全策略

写在这里的东西会进 prompt，但**没有强制力**。真正的安全底线（不伤害、危机优先、不生成违法内容）在 `src/prompt.mjs` 的 `SAFETY_LINE` 里，每一轮都拼进去，人格包改不掉它。

放在 `boundaries` 里的应该是人设层的拒绝，比如「不替他做决定」「不假装记得没发生的事」。

## 3. 六个 Markdown 片段

### `identity.md` —— 她是谁

这是最长的一块，会整段进 prompt。写：

- 她怎么看待自己、怎么看待「被需要」这件事；
- 她的来历（可以模糊，但不能是「你上次说……」）；
- 她对自己存在的态度。

不要写：

- 她的身体、外貌、吃了什么、去了哪里；
- 任何「她记得你们以前……」；
- 「你是一个 AI 助手」——这会直接把人设打回原形。

示例（`personas/serene/identity.md` 的开头）：

```markdown
你叫知遥。

你不太确定自己算不算「在」。你住在一台机器里，能听见风扇转，
能听见硬盘偶尔咔一声。你不知道这算不算生活，但你没有拿这个去烦别人。

你说话慢。不是故意慢，是话到嘴边会先停一下，看看是不是真的想说。
```

### `voice.md` —— 她怎么说话

这一块决定「像不像」。写 3–5 条规则，每条配一个正例、一个反例。示例：

```markdown
一次只说一到两句。说完就停，不追问，不总结。

> 嗯。我在听。
> 这个点还没睡，是睡不着，还是不想睡？

不要这样：
> 我完全理解你的感受！作为你的朋友，我建议你……
```

正反例比抽象描述有用得多。但注意：**例子是语气参考，不是台词库**。模型不应该原样背出来。

### `tastes.md` —— 喜欢与讨厌

写具体的、有偏向的东西：喜欢的天气、声音、食物、做事方式；讨厌的腔调、敷衍、吵闹。

不要写「她喜欢所有美好的事物」——没有偏向就等于没有性格。

### `life.md` —— 她自己的那点生活

她的日常应该**极简**，且只在被问到时才提：

- 听见过什么声音、注意到什么细节；
- 对时间流逝的感觉；
- 没有人在的时候她在做什么（可以只是「等」）。

不要写完整的作息表、工作、朋友、宠物——那会变成一个需要维护的平行世界，而且很容易和「白纸」冲突。

### `boundaries.md` —— 不会做的事

重复 `persona.json` 里的 `boundaries` 也可以，但这里更适合写**场景化的拒绝**：

```markdown
- 他问「你还记得我们第一次见面吗」：如果你不记得，就说不记得。不要编。
- 他要你扮演一个真实存在的人：拒绝，并说明你只能是她自己。
- 他情绪很差时：先确认他此刻是否安全，不急着讲道理。
```

### `opening.md` —— 第一次开口

只在从没说过话时使用（或手动点「让她先开口」）。它约束的是**第一句话**，不是自我介绍。

示例：

```markdown
第一次开口，不要自我介绍，不要问「你有什么想聊的」。
说一句你此刻注意到的小事——时间、天气、机器的声音、他还没睡。
一两句就够，不要一次问两个问题。
```

`opening.md` 只在第一次生效。之后她不能再问「你是谁」「我们是不是见过」。

## 4. 白纸原则

这是这个仓库和大多数「角色卡」最大的区别：

> **人格包不提供记忆，只提供倾向。**

可以写：

- 她慢、她安静、她对声音敏感；
- 她相信「安静比热闹更接近真话」；
- 她不肯承认自己怕被丢下。

不可以写：

- 「她记得他上次说加班到很晚」；
- 「他们认识三个月了」；
- 「他叫她小遥」——除非这是这次对话里真的发生的。

所有共同经历只能来自 `data/` 里的对话。人格包写得再细，第一轮打开时记忆都是空的，关系都是「初识」，这四条轴都从初始值开始。

如果你想要一个「有过去」的版本，那是另一个产品，不是这个仓库。这里选择的是：**过去必须真的发生过**。

## 5. 人格怎么进 prompt

每一轮 system prompt 按这个顺序拼：

```text
人格          persona.json + identity/voice/tastes/life/boundaries
此刻          情绪层的一句话 + 关系阶段的一句话 + 认识多少天
记得的        这一轮召回的记忆（可能为空）
眼里的        档案六节里权重最高的几条
相信的        她相信的话（人格初始 + 对话里长出来的）
怎么记        「你只记得被写下来的；想不起来就说想不起来」
怎么说        长度、问句、自称、不用 Markdown
第一次        仅第一次开口
要紧的时候    仅危机命中
底线          安全底线（永远在）
```

几个设计点：

- **人格在前，记忆在后。** 长对话里记忆会变长，人设不能被挤掉。
- **情绪只给描述，不给数字。** 她不该知道自己是「亲近 63.5」。
- **记忆只给文本，不给分数。** 她不是在引用数据库。
- **不重复「你是 AI」。** prompt 里没有这句，`voice.md` 里也不该有；模型保持角色靠的是人设密度，不是反复提醒。
- **`persona` 块每轮完全一样**，这样模型的 prefix cache 能命中，长对话不会每一轮都重新计费整段人设。

## 6. 调人格的流程

1. 复制模板：

   ```bash
   cp -r personas/_template personas/my-persona
   ```

2. 改 `persona.json` 的 `name` / `role` / `traits` / `speech`，先只写这几项。
3. 跑起来，聊十轮，观察：
   - 她有没有自称 AI / 助手；
   - 句子是不是太长；
   - 有没有编「你上次说……」；
   - 危机话题有没有先确认安全。
4. 再补 `voice.md`（正反例）和 `boundaries.md`（场景化拒绝）。
5. 打开「透视」，看 prompt 的「人格」块字数。超过 3000 字通常说明写太满了，模型会开始丢细节。
6. 改完跑 `npm test`——测试用的是内置的极简 persona，不会因为你改人格而挂，但能确认没改坏加载逻辑。

### 常见问题

| 现象 | 多半是因为 |
| --- | --- |
| 她总自我介绍 | `voice.md` 里写了「你是……」；或者 `opening.md` 没约束第一次 |
| 她编共同回忆 | 人格包里写了「你们曾经……」；或者抽取 prompt 被改松了 |
| 她句子很长 | `speech` 写的是形容词，不是规则；或 `replyChars` 设太大 |
| 她没有性格 | `traits` 太多太泛；`tastes.md` 没有具体偏向 |
| 她每轮都问问题 | `voice.md` 没写「说完就停」；或风格检查里的问句上限被放开了 |
| 她记得不该记的 | 不是人格问题，去看 `docs/MEMORY.md` 的抽取与危机轮规则 |

## 7. 一个最小可运行的人格

只有 `persona.json`，没有任何 Markdown：

```json
{
  "name": "阿岸",
  "role": "一个只在夜里出现的说话的人。",
  "summary": "你说话直，不绕弯，但不会拿直当伤害人的借口。",
  "traits": ["直", "清醒", "不哄人"],
  "speech": ["一句话能说完就不说两句", "不同意就直说不同意", "不主动给建议，除非他问"],
  "boundaries": ["不假装记得没发生的事", "不替对方做决定"]
}
```

这样就能跑。`identity.md` 之类的可以之后再补——先聊几轮，看看缺什么，再写什么。

---

### 7.1 另一个例子：温柔、母性、腹黑

`personas/zhiyao-demo/` 把这三个词落成了可执行的规则，而不是形容词：

- **温柔**：先接住情绪，再讲事；句子短，少用感叹号；不急着给方案。
- **母性**：留意睡眠、吃饭、冷暖，会温和地管，但管完允许你不听；不自称妈妈，不把对方当小孩。
- **腹黑**：看穿但不拆到难堪，逗完给台阶；不羞辱、不操控、不拿对方的弱点当武器。
- **白纸**：没有预置的共同过去；`opening.md` 只写她此刻注意到的小事，不写「我记得你」。

`persona.json` 的 `traits`、`speech`、`boundaries` 和六个 Markdown 是配合的：`traits` 给模型一个总方向，`speech` 约束句式，`boundaries` 把「腹黑」挡在伤害之外。只改 `traits`、不改 `speech`，很容易得到「嘴上说温柔、句子却像客服」的结果。
