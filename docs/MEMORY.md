# 记忆是怎么工作的

这份文档写的是本仓库**实际在用**的参数和公式，不是设计愿景。想改任何一个数，先读一遍最后一节「改参数之前」。

记忆不是聊天记录。聊天记录是「她说过什么」，记忆是「她记住了什么」——后者更少、更慢、会变形，也会被忘掉。

---

## 1. 一条记忆长什么样

```json
{
  "id": "m_lq3k8x_7fa2",
  "text": "他工作很忙，经常加班到很晚",
  "kind": "fact",
  "importance": 0.8,
  "evidence": ["加班到十一点"],
  "createdAt": 1767225600000,
  "updatedAt": 1767225600000,
  "stability": 6.3,
  "pinned": false,
  "archived": false
}
```

| 字段 | 说明 |
| --- | --- |
| `text` | 一条记忆的正文，**最多 80 字**。写不短说明还没想清楚。 |
| `kind` | 六类之一：`fact` / `preference` / `moment` / `promise` / `insight` / `self` |
| `importance` | 0.1–1。名字、重要的人、承诺、伤口 ≥ 0.8；口味、习惯 0.5；一次性的 0.2。 |
| `evidence` | 他当时的原话，**每条最多 24 字，最多 3 条**，一个字都不改写。 |
| `createdAt` | 写入时间。**保持率永远从这里算**，被想起不重置年龄。 |
| `stability` | 稳定度（天）。写入时由 `importance` 和 `kind` 算出，之后只会因为「被用上」变长。 |
| `pinned` | 钉住：不参与容量淘汰，但**仍然会衰减**。 |
| `archived` | 归档：不再参与召回，但还查得到。 |

`evidence` 不是装饰。它是防止「概括越漂越远」的锚：三个月后你看到「他工作很忙」，还能看见当时那句「加班到十一点」，判断这条记忆是不是已经过时。

### 六类

| kind | 写什么 | 例子 |
| --- | --- | --- |
| `fact` | 可核对的事实 | 他住在城南；他养了一只猫 |
| `preference` | 喜欢 / 厌恶 | 他受不了空调直吹 |
| `moment` | 值得留下的一刻 | 他凌晨三点说「还好你在」 |
| `promise` | 明确答应过的事（双方都算） | 他答应下周去看医生 |
| `insight` | 他讲明白的一个道理 / 看事情的方式 | 他觉得安慰人之前先别急着给方案 |
| `self` | 他怎么看自己 | 他说自己一累就不爱说话 |

`moment` 和 `promise` 的初始稳定度 ×1.3——它们本来就该记得久一点。

## 2. 写：每轮最多两条，宁可漏

每轮回复之后，`src/extract.mjs` 会单独发一次模型调用，要求只输出：

```json
{
  "memories": [{ "text": "…", "kind": "fact", "importance": 0.6, "evidence": ["他的原话"] }],
  "growth": [],
  "beliefs": []
}
```

硬约束：

- 每轮最多 **2 条记忆、2 条档案、1 条看法**；主动整理（`/api/reflect`）最多 **3 / 3 / 2**。
- 只写「他说的、关于他的、以后还用得上的」。寒暄、天气、一次性的情绪不写。
- 她自己的话不进记忆——她说过什么在聊天记录里，不在「她记得的事」里。
- 没有原话就不写这条。
- 一条都挑不出来就返回空数组，**不凑数**。

失败处理：模型吐坏 JSON → 这一轮什么都不写，回复照常。抽取失败永远不会变成「她没说话」。每个失败原因会记在透视的 `extractionError` 里。

### 危机轮不写

`src/core/crisis.js` 命中高风险时，这一轮**跳过抽取**，透视里的 `extractionSkipped` 会写明原因。

理由不是「不配记住」，是召回不可控：如果「他说过不想活」变成一条长期记忆，以后任何一次情绪低落都可能把它召回进 prompt。先处理当下，不在这个时刻做长期存档。

## 3. 存：追加日志，不改历史行

`data/memories.jsonl` 一行一条 JSON，只往后加：

| 行类型 | 作用 |
| --- | --- |
| 记忆本体 | 一条新记忆 |
| `{"type":"reinforce","id":…}` | 被想起 / 被用上了一次 |
| `{"type":"patch","id":…}` | 手动改过（文本、类型、重要度、钉住、归档） |
| `{"type":"merge","id":…}` | 抽取出来和旧记忆重复，合并 |
| `{"type":"forget","id":…,"reason":…}` | 忘了（容量 / 过期 / 手动） |

好处：

- 进程被杀不会留下半截 JSON；
- 「她忘了什么」和「她记得什么」一样可查；
- 任何一条现在的样子，都能从日志重放出来。

启动时整个文件读进内存（容量上限 500，不需要数据库），之后每次写都 `appendFileSync`。

### 去重合并

新记忆先和现有记忆比词面 Jaccard 相似度（中文按二字组，英文按词）。**≥ 0.8 判定为同一件事**：

- 文本取两边更长的那条（新说法通常更完整）；
- `importance` 取较高值；
- 两边的 `evidence` 合并，最多 3 条；
- 写一行 `merge`，不新增一条。

没有用向量相似度，是因为要可解释：你能在透视里看见「为什么这两条被并了」，而不是一个 0.87 的黑箱分数。

## 4. 想：激活度 + 确定性抽样，允许 0 条

召回发生在每次拼 prompt 之前，用**他这一句话**作为查询。

### 4.1 线索分

```text
cue = Σ(查询词在记忆里的权重) / sqrt(查询词数)
```

中文切二字组，英文按词并做轻量词形归一。线索分低于 **0.12** 的记忆直接淘汰——不补位。

例外是**专名锚点**：查询里的拉丁词（`ComfyUI`、`4090ti`、`Rust`）如果在整个记忆语料里出现次数 ≤ 10，就当成锚点；只要某条记忆里也有它，就绕过 0.12 的门槛。这是为了「上次那个 ComfyUI 的报错」这类查询——专名只占一两个词，按句长一除就掉到门槛以下。

`SERENE_MEMORY_ANCHORS`：`latin`（默认，只认拉丁专名）/ `rare`（还认低频中文词）/ `off`（完全关掉）。

### 4.2 保持率

```text
retention = (1 + 年龄天数 / 稳定度) ^ −0.6
```

- 年龄从 `createdAt` 算，**被想起不会让「多久以前」变新**。
- 稳定度初始：`(1.5 + 6 × importance) × (moment|promise ? 1.3 : 1)`，封顶 3650 天。
- 所以 importance 0.8 的事实，稳定度约 6.3 天；45 天后保持率约 0.28，一年后约 0.09。
- 一次性的 0.2，稳定度 2.7 天；两周后只剩约 0.3。

### 4.3 激活度

```text
activation = 1.1 × ln(retention + 0.02)
           + 0.9 × cue
           + 0.5 × importance
           + moodTint
           + 0.4 × Gumbel(seed)
```

- `moodTint`：心情只给非 `fact` 记忆染色（±0.45），事实不染。心情改的是「哪条更容易浮起来」，不改内容、不改真假。
- `Gumbel` 噪声的种子是 `(id, 查询, 当前时间)` 的 FNV-1a 哈希，**不用 `Math.random`**：同样的输入永远得到同样的结果，测试才钉得住，也才能解释「为什么这次是它」。
- 排序后取前 `recallLimit` 条（默认 5，设置里最多 8）；分数低于 **−1.2** 的全部丢掉。**允许返回空数组。**

召回结果里每条都带 `score`、`cue`、`retention`、`anchored`，透视面板直接展示——包括「它本来不够格，是被那个名字捞回来的」。

### 4.4 被用上才变牢

只有**真的出现在回复里**的记忆才加固。判断方式是回复文本和记忆文本的词面重叠：

- 记忆 ≤ 8 个 token：重叠 ≥ 1 个就算用上；
- 更长：重叠 ≥ 2 个。

```text
r  = (1 + 间隔天数 / 稳定度) ^ −0.6
S' = S × (1 + 1.2 × (1 − r))      // 封顶 3650 天
```

同一刻连想两次，`r ≈ 1`，几乎不长；隔一阵再想起来才明显。这是间隔效应本身，不是 bug。

### 4.5 容量与遗忘

- 容量 **500**。写满时先挤掉已经过期的，再挤「保持率 × 重要度」最低的**未钉住**记忆，写一行 `forget`，`reason: "capacity"`。
- 手动「忘掉」也是写 `forget`，不是删行；面板里能看见忘掉了什么。
- 归档是 `patch { archived: true }`：不参与召回，但还查得到，可以恢复。

## 5. 读：她怎么「用」这些记忆

拼 prompt 时，记忆只占一块，且**只写文本，不写分数**：

```text
你记得的：
- 他工作很忙，经常加班到很晚
- 他受不了空调直吹
```

不会写「记忆相关度 0.73」——她不该知道自己是几分。也不会写「根据记忆 3」——她不是在引用数据库。

记忆块排在人格之后、规则与底线之前。这样长对话里人设不会被记忆挤掉，底线也永远在最后。

## 6. 主动整理

聊天面板上的「整理记忆」调用 `/api/reflect`：把最近 60 条对话、现有记忆、现有档案一起给模型，只找**跨轮次反复出现**的东西。

- 上限 3 条记忆 / 3 条档案 / 2 条看法，比每轮抽取更苛刻；
- 要求「不要重复她已经记着的；没有新的就返回空数组」；
- 结果同样走去重合并，不会因为整理一次就翻倍；
- 需要你手动点，不会在后台自己跑。

---

## 7. 调试与观察

- **透视**：每轮一份，含完整 prompt 分块与字数、召回列表与分数、情绪前后、写入结果、风格检查。`data/traces.jsonl` 留最近 80 轮。
- **记忆面板**：搜索、按类型筛、看保持率条、看原话、钉住 / 改 / 忘掉、看归档。
- **导出**：`GET /api/export` 是纯 JSON，方便你写脚本分析「她这三个月记住了什么」。

## 8. 改参数之前

这些数字是彼此咬合的，单独调一个通常不会得到你想要的效果：

| 想改的效果 | 该动的地方 | 连带影响 |
| --- | --- | --- |
| 她记得更牢 | `importance` 抽取标准、`RECALL.retentionWeight` | 记忆更容易「赖着不走」，旧事会反复出现 |
| 她更容易想起旧事 | 降低 `minCue`、提高 `recallLimit` | prompt 变长，当前话题被稀释 |
| 她忘得更快 | 缩短稳定度公式里的系数、降低容量 | 需要更频繁地重新说同一件事 |
| 少编记忆 | 收紧抽取 prompt、把每轮上限降到 1 | 漏得更多，长对话后档案会偏薄 |
| 档案长快一点 | 提高每节上限 | 面板变长，prompt 里的档案块会挤压其他部分 |

改完至少跑一遍 `npm test`；召回相关的改动请同时更新本文档和 `tests/core.test.mjs` 里的期望值。
